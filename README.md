## 🛠️ 구현 방법

### 1️⃣ 회원 가입 API

- **엔드포인트**: `POST /user/signup`
- **구현 내용**:
    - 사용자의 아이디, 이름, 비밀번호, 식별타입, 식별값을 받아 새로운 사용자 생성
    - 식별타입은 주민등록번호(REG_NO) , 사업자등록번호(BUSINESS_NO) 로 구성
    - 사용자 ID, 이름, 식별값 암호화 처리
    - 비밀번호는 **CustomPasswordEncoder**를 구현하여 다른 컬럼과 동일한 암호화 방식으로 저장
    - 사용자 아이디값(이메일 형식) 을 유니크로 설정

### 2️⃣ 로그인 API

- **엔드포인트**: `POST /user/login`
- **구현 내용**:
    - 이메일과 비밀번호를 받아 인증 처리
    - 인증 성공 시 **JWT 토큰** 발급
    - 인증 토큰 유효기간 30분 설정

### 3️⃣ 송금 견적서를 갖고 오는 API

- **엔드포인트**: `POST /transfer/quote`
- **구현 내용**:
    - 금액 범위별 수수료 구간 차등 설정
    - 수수료 = (보내는 금액 * 수수료율) + 고정수수료
    - 받는 금액 = (보내는 금액 - 수수료) / 환율
    - 소수점 자리수는 Java Util Currency 의 defaultFractionDigits 로 설정
    - 견적서 만료시간은 발급 후 +10분
    - 재사용 불가하게 구현
    - 환율 정보 api 조회후 요청 통화 수수료 계산
    - usd 환율정보 기본값으로 입력

### 4️⃣ 송금 접수 요청 API

- **엔드포인트**: `POST /transfer/request`
- **구현 내용**:
    - 이전에 발행한 견적서 ID 를 전달하여 요청
    - 견적서 시간 만료시 익셉션 발생
    - 개인 회원 법인 회원 식별값 분리하여 구분
    - 개인회원은 하루에 $1000 이상금액은 익셉션 발생
    - 법인회원은 하루에 $5000 이상금액은 익셥션 발생

### 5️⃣ 회원의 거래 이력을 가지고 오는 API

- **엔드포인트**: `GET /transfer/list`
- **구현 내용**:
    - 로그인한 회원의 거래내역을 가져오는 API
    - 송금을 접수한 내역들을 조회하고, 오늘의 주요 정보들을 전달

## ✅ 검증 결과 및 회고

### 🔹 검증 결과
- **Junit**을 이용하여 각 API 서비스에 대한 테스트 진행
- **Swagger**을 이용하여 각 API 엔드포인트에 대한 테스트 진행
- 회원등록, 로그인, 송금 견적서, 송금 접수, 거래이력 기능이 정상적으로 동작함을 확인
- JWT 토큰을 통한 인증 및 권한 부여 로직이 예상대로 작동함을 검증
- Junit에 Mock 사용사 설정 가능하도록 한후 검증


### 🔹 회고
✅ **잘된 점**
- **JWT**를 활용한 인증 및 권한 부여로 보안 강화
- **CustomPasswordEncoder**를 사용한 비밀번호 암호화로 사용자 정보 보호
- **Swagger**을 활용한 API 문서화 구성
- 체계적인 API 테스트로 신뢰성 확보

🔸 **개선할 점**
- **예외 처리** 로직을 더욱 세분화하여 사용자에게 명확한 에러 메시지 제공 필요
- **API 문서화**를 조금 더 세밀하게 설정하여 개발자 및 사용자 간의 소통 강화 필요
- **테스트 케이스**를 추가하여 다양한 시나리오에 대한 검증 강화

### 📌 개선 방향
- **예외 처리**: 다양한 예외 상황에 대한 처리 로직을 추가하고, 사용자에게 친숙한 에러 메시지를 제공하도록 개선
- **API 문서화**: Schema 등을 활용하여 컬럼들에대한 세부적인 사항을 작성하여 유지보수 용이성 향상
- **테스트 강화**: 단위 테스트 및 통합 테스트를 추가하여 코드의 안정성과 신뢰성 확보
